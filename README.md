# AI API Store Hub

Operated by **Operava Technologies**.

- Minimum prepaid wallet top-up: PHP 100.
- Target gross margin: 30% (selling price = verified provider cost / 0.70).
- Customer API keys are generated by the platform; only hashes are stored.
- AI runtime: Cloudflare Workers AI, with AI Gateway routing configured per deployment.
- Payments: PayMongo Hosted Checkout v2 and signed webhook confirmation.

## PayMongo setup
Set Worker secrets `PAYMONGO_SECRET_KEY`, `PAYMONGO_WEBHOOK_SECRET`, and `SESSION_SECRET`. Set `PAYMONGO_MODE=test` for staging or `live` for production. Register `https://YOUR_DOMAIN/webhooks/paymongo` for `checkout_session.payment.paid`. The webhook signing secret is different from the API secret. Browser redirects never credit wallets.

## API
- `POST /auth/register`, `POST /auth/login`
- `POST /keys`
- `POST /billing/checkout` (minimum PHP 100)
- `GET /billing/wallet`
- `POST /webhooks/paymongo`
- `GET /v1/models`, `POST /v1/chat/completions`

## Database
Apply `src/db/schema.sql`, then `src/db/migrations/0002_paymongo_wallet.sql`. Never apply a migration to production before taking a backup and validating the target D1 database.

## Pricing
All wallet values are PHP. Verify provider model costs and the USD/PHP exchange rate before enabling a model. Use the exact 30% gross-margin formula, not a 30% markup. Model price configuration must be owner-controlled and auditable.

## Production requirements
Configure the production D1 binding, Cloudflare AI binding/Gateway, PayMongo live credentials and webhook, session secret, and verified per-model costs. Test duplicate webhook delivery, failed/cancelled checkout, replayed signatures, insufficient balance and refunds before accepting live payments.
